# Style Guide

- Пояснення для людей пишуться українською.
- Імена файлів, заголовки документів, IDs, status values, paths, commands,
  configuration keys і технічні labels пишуться англійською.
- Використовуйте стандартні Markdown-посилання та відносні paths.
- Не дублюйте повний контракт зі specification; посилайтеся на нього.
- Відокремлюйте факт, припущення, decision і open question.
- Не описуйте незавершену поведінку як implemented.
- Для змін із delivery-впливом зазначайте scope, acceptance, validation і
  documentation impact.
